This project provides Spring Boot auto-configuration and lifecycle management for the https://www.quickfixj.org/[QuickFIX/J] FIX protocol engine.
It can create either a QuickFIX/J `Acceptor` or `Initiator`, supply the standard supporting components, and start and stop the connector with the Spring application context.

In starter property names, _server_ means QuickFIX/J `Acceptor` and _client_ means QuickFIX/J `Initiator`.

== Compatibility

The current release is `{current-version}` for Spring Boot 4.0 and Java 17 or later.
The `main` branch is preparing starter 4.4.x for Spring Boot 4.1.
See the link:docs/compatibility.adoc[compatibility matrix] before upgrading between starter lines.

[NOTE]
====
Starter 4.x supports one auto-configured role per application context.
If an application needs both an `Acceptor` and an `Initiator`, or multiple connectors of one role, use separate child contexts.
The reason and planned replacement are described in link:docs/migration.adoc[Migration] and link:docs/adr/0002-client-server-composition.adoc[ADR 0002].
====

== Quick start

The following example selects FIX 4.4.
Replace `quickfixj-messages-fix44` with the message artifact required by your sessions.

=== 1. Add the dependencies

Import the starter POM to use its managed QuickFIX/J version, then add the starter and the required FIX message artifact:

[source,xml,subs="+attributes"]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>io.allune</groupId>
            <artifactId>quickfixj-spring-boot-starter</artifactId>
            <version>{current-version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>io.allune</groupId>
        <artifactId>quickfixj-spring-boot-starter</artifactId>
    </dependency>
    <dependency>
        <groupId>org.quickfixj</groupId>
        <artifactId>quickfixj-messages-fix44</artifactId>
    </dependency>
</dependencies>
----

FIX message artifacts are optional starter dependencies and are not added automatically.
This keeps applications free to include only the protocols they use.
See link:docs/getting-started.adoc[Getting started] for the complete artifact list and dependency alternatives.

=== 2. Create the application

A regular Spring Boot application is sufficient:

[source,java]
----
@SpringBootApplication
public class FixApplication {

    public static void main(String[] args) {
        SpringApplication.run(FixApplication.class, args);
    }
}
----

The starter supplies an `Application`, `MessageStoreFactory`, `LogFactory`, `MessageFactory`, connector, and lifecycle manager unless the application provides replacements.

=== 3. Choose one role

==== Acceptor

Add the following application properties:

[source,properties]
----
quickfixj.server.enabled=true
quickfixj.server.config=classpath:quickfixj-server.cfg
----

Create `src/main/resources/quickfixj-server.cfg`:

[source,ini]
----
[default]
ConnectionType=acceptor
StartTime=00:00:00
EndTime=00:00:00
HeartBtInt=30
UseDataDictionary=Y

[session]
BeginString=FIX.4.4
SenderCompID=EXECUTOR
TargetCompID=CLIENT
SocketAcceptPort=9876
----

==== Initiator

Add the following application properties:

[source,properties]
----
quickfixj.client.enabled=true
quickfixj.client.config=classpath:quickfixj-client.cfg
----

Create `src/main/resources/quickfixj-client.cfg`:

[source,ini]
----
[default]
ConnectionType=initiator
StartTime=00:00:00
EndTime=00:00:00
HeartBtInt=30
ReconnectInterval=5
SocketConnectHost=localhost
UseDataDictionary=Y

[session]
BeginString=FIX.4.4
SenderCompID=CLIENT
TargetCompID=EXECUTOR
SocketConnectPort=9876
----

Run the application normally.
By default the connector starts with the Spring context, uses in-memory message storage, logs to the screen, and publishes QuickFIX/J callbacks as Spring application events.

The project actively maintains `main` for Spring Boot 4 and maintains the `3.x` branch for compatible high-value and security fixes.
See the link:ROADMAP.adoc[roadmap], link:docs/support-policy.adoc[support policy], and link:CONTRIBUTING.adoc[contribution guide].
