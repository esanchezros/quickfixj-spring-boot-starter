Patch versions shown above describe the versions used to build and test the project. Applications should use a compatible patch from the same supported line unless a release note states a stricter requirement.

== Verification policy

Each maintained line should verify:

* Its minimum Java version and a current Long-Term Support (LTS) Java version.
* The Spring Boot line owned by that branch.
* The current supported QuickFIX/J patch and proposed upgrades.
* Operation with Actuator present and absent, once Actuator becomes optional.
* A minimal consumer application built from the packaged artifacts.
* Binary and source compatibility with the previous release in the same major line.
* Maven dependency convergence and the intended optional-dependency behavior.

The test matrix will expand as the work in link:../ROADMAP.adoc[the roadmap] is delivered.

== Versioning changes

A dependency upgrade can be incompatible even when this project's Java API does not change. Release notes must identify changes to the supported Spring Boot, QuickFIX/J, Java, Maven, and transitive dependency baselines.

See link:adr/0001-versioning-policy.adoc[ADR 0001] for the versioning decision.
